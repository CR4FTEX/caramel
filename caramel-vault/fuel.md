# Furnace fuel and compost

How an item's burn time and compost chance are set in Minecraft 26.3, and how Caramel changes them. The code is `io.github.cr4ftex.caramel.fuel.CraftedFuel` and `io.github.cr4ftex.caramel.compost.CraftedCompost`, with the datagen providers `CaramelBurnTimeProvider` and `CaramelCompostProvider`; the decisions behind them are in ideas C-001, C-003, C-004, C-006 and C-007 in `docs/DESIGN.md`. Checked in bytecode and in game tests.

## How fuel works

- Fuel is the item data component `minecraft:cooking_fuel` (`DataComponents.COOKING_FUEL`), a `CookingFuel(ResolvableInt burnTime, ResolvableFloat speedMultiplier)`. Items get it through `Item.Properties.cookingFuel(key)`, which pairs the burn-time key with the speed key `minecraft:cooking/speed_default` (`ContextFloatProviders.COOKING_DEFAULT_SPEED_MULTIPLIER`, `javap -c`).
- The burn time is a reference into the reloadable registry `context_int_provider`: for example `minecraft:cooking/time_wood_blocks` (planks, wooden stairs, wooden pressure plates, wooden fences, wooden trapdoors), `minecraft:cooking/time_wood_items_large` (wooden doors, 200 ticks), `minecraft:cooking/time_wood_items_extra_small` (wooden buttons and the bowl, 100 ticks) and `minecraft:cooking/time_wool` (wool, wool stairs). Slabs have their own entries, at half their block's value, and wool carpets theirs, 67 ticks.
- Each `cooking/time_*` entry is `div(n, ...)`. The divisor is `cooking/fast_burn_time_reduction_factor` (2) where `minecraft:block/fast_cooking` matches (the blast furnace and the smoker), and `cooking/normal_burn_time_reduction_factor` (1) elsewhere. The division is integer division (`Quotient`, `idiv`). `ContextIntProviders.cooking(predicates, normal, fast, n)` builds one exactly like vanilla does.
- A furnace reads the burn time through `AbstractFurnaceBlockEntity.getBurnDuration(ServerLevel, ItemStack)`, in its own loot context. Its fuel slot accepts any item that has the component (`canPlaceItem`), and it lights and consumes the item only for a burn time above 0 (`serverTick`). The client never computes a burn time: no class in the client-only jar references `CookingFuel` or `ResolvableInt`.
- The speed multiplier is a reference into the reloadable registry `context_float_provider`. `cooking/speed_default` is a `conditional`: `cooking/fast_speed_multiplier` (2.0) where `minecraft:block/fast_cooking` matches, `cooking/normal_speed_multiplier` (1.0) elsewhere. Each fuel item that lights sets the furnace's `speedMultiplier` (1.0 from its constructor until then), and a smelt takes `ceil(cookingtime / speedMultiplier)` ticks, divided in `float` (`AbstractFurnaceBlockEntity.getTotalCookTime`). Every vanilla smelting (73), blasting (25) and smoking (9) recipe has `cookingtime` 200 (`data/minecraft/recipe/`), so a blast furnace or smoker takes 100 ticks per smelt and burns each fuel half as long, rounded down.
- Each time a new fuel item lights mid-smelt, `serverTick` rescales the cooking progress to that fuel's speed in `float` arithmetic and rounds it up with `Math.ceil`, which can add a tick. By a float32 simulation of that code (`javap -c`), a relight adds one at progress 15, 27, 30, 54, 60, 107, 108, 119 or 120 of a 200-tick smelt, and at 15, 27, 30, 54 or 60 of a 100-tick one. Caramel's 15-tick wooden buttons, lit with a smelt in an unlit furnace, gain a tick at 15 and none at the later relights (31, 46 and on): 14 finish a 200-tick smelt, and 13 reach 196. Count fuel items against a smelt by simulating it, never by dividing burn times.

## How compost works

- Compost is the item data component `minecraft:compostable` (`DataComponents.COMPOSTABLE`), a `Compostable(ResolvableInt layers)` referencing a `context_int_provider` entry: `minecraft:compostable/low` (30%), `low_medium` (50%), `medium` (65%), `medium_high` (85%) or `always_add_one`. Moss and pale moss carpets are `low`, their blocks `medium` (read from the components in a game test).
- Each chance is a `number_dispatcher`: 1 when the composter's `level` is 0, so the first item into an empty composter always adds a layer, and otherwise a `weighted_list` of 1 (weight n) and 0 (weight 100 - n). `ContextIntProviders.compostable(blocks, n)` builds one exactly like vanilla's.

## How Caramel changes them

- New burn times and compost chances are data, generated into `data/caramel/context_int_provider/cooking/` by `CaramelBurnTimeProvider` and `data/caramel/context_int_provider/compostable/` by `CaramelCompostProvider` (each a `FabricCodecDataProvider` with `ContextIntProviders.DIRECT_CODEC`).
- Items are pointed at them with Fabric API's `DefaultItemComponentEvents.MODIFY` from common init, not a mixin. The event runs every time the item components are bound, on the server and on a connected client alike, after vanilla binds its defaults, so a change never stacks.
- `CraftedFuel` matches an item by a pair: its block's class (`StairBlock`, `PressurePlateBlock`, `WoolCarpetBlock`, `FenceBlock`, `DoorBlock`, `TrapDoorBlock`, `ButtonBlock`) and vanilla's burn-time key. The class is needed because `time_wood_blocks` is shared by planks, stairs, plates and more, `time_wood_items_large` by wooden doors, signs, the wooden tools and the wooden spear, and `time_wood_items_extra_small` by wooden buttons and the bowl (`javap -c` on `Items`). `CraftedCompost` names its two items and changes them only while their value is vanilla's `compostable/low`.
- `CraftedFuel` replaces only the burn time and keeps the item's speed multiplier (`CraftedFuel.register`). Each idea's `...ThatBurnedStillBurn` game test compares every burning item's speed in the furnace, blast furnace and smoker with vanilla's, and `onlyVanillaItemsCraftedCheaperThatBurnedHaveNewFuel` fails when Caramel's data pack holds a `minecraft` file under `context_int_provider`, `context_float_provider` or `predicate`.
- Each new burn time is what the item costs in its block, rounded down, so crafting never adds fuel. The game tests `craftingStairsNeverAddsFuel`, `craftingPressurePlatesAndCarpetsNeverAddsFuel`, `craftingFencesNeverAddsFuel`, `craftingFenceGatesNeverAddsFuel`, `craftingWoodenDoorsAndTrapdoorsNeverAddsFuel` and `craftingButtonsNeverAddsFuel` compute that cost from vanilla's recipes and burn times (see [[gametest]]); the values and the owner's choices are in `docs/DESIGN.md`. A stick is costed by vanilla's `minecraft:stick` recipe, 2 planks for 4, never by its burn time, 100 ticks against a plank's 300 (`cooking/time_dry_plants`); `MorePerCraft.craftingNeverAddsFuel` reads the recipe.
- The change is to the item's default components, which every stack reads unless its own patch sets that component (`ItemStack` keeps a `PatchedDataComponentMap`): a wooden pressure plate found in a village burns Caramel's burn time, and a moss carpet grown with bone meal composts at Caramel's chance.
- Only vanilla items are changed: the predicate checks the `minecraft` namespace rather than a tag such as `#minecraft:stairs`, because any mod can add its items to a tag. The scope is the owner's answer under "Fuel scope" in C-001, `docs/DESIGN.md`.
- Vanilla's own fuel and compost for an item come from `BuiltInRegistries.DATA_COMPONENT_INITIALIZERS.build(...)`, which Fabric's modify event never touches; the game tests read them there (see [[gametest]]).

## Traps

- **A missing burn-time file makes the item useless as fuel, silently.** A `CookingFuel` whose key does not resolve falls back to 0 (`ResolvableInt$Reference.get`). The fuel slot still takes the item, but the furnace never lights and never consumes it, and no log line names the missing file. The game tests `craftingStairsNeverAddsFuel`, `stairsThatBurnedStillBurn`, `craftingPressurePlatesAndCarpetsNeverAddsFuel`, `pressurePlatesAndCarpetsThatBurnedStillBurn`, `craftingFencesNeverAddsFuel`, `fencesThatBurnedStillBurn`, `craftingWoodenDoorsAndTrapdoorsNeverAddsFuel`, `woodenDoorsAndTrapdoorsThatBurnedStillBurn`, `craftingButtonsNeverAddsFuel` and `buttonsThatBurnedStillBurn` catch it (see [[gametest]]); generated files left uncommitted are one way it goes missing (see [[datagen]]).
